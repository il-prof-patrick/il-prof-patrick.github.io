Come funziona il Web

1.1Internet e Web

Internet e Web sono la stessa cosa? Fate un esempio di qualcosa che usa Internet ma non è il Web.

Internet è la rete mondiale che collega fra loro miliardi di dispositivi (computer, telefoni, server, router) e permette di scambiare dati usando regole comuni, i protocolli della famiglia TCP/IP. Internet è l’infrastruttura: cavi, fibre, antenne, router e le regole per far viaggiare i pacchetti di dati.

Il Web (World Wide Web, “ragnatela grande quanto il mondo”) è invece un servizio che funziona sopra Internet: un insieme enorme di documenti, le pagine web, collegati fra loro da link. Ogni pagina ha un indirizzo, si chiede con il protocollo HTTP e si legge con un programma chiamato browser.

Esempio

Analogia. Internet è la rete delle strade; il Web è uno dei servizi che usano quelle strade, come i corrieri che consegnano pacchi. Sulle stesse strade viaggiano anche autobus, ambulanze e taxi, cioè altri servizi (e-mail, chat, giochi online, videochiamate). L’analogia ha un limite: su Internet i servizi non hanno “mezzi” diversi, ma usano tutti gli stessi pacchetti di dati con protocolli diversi.

Errore tipico

«Se non funziona Google, non funziona Internet.»

Google è un sito, cioè un servizio del Web ospitato su certi server. Se quei server hanno un problema, Internet continua a funzionare: WhatsApp, la posta e gli altri siti funzionano lo stesso. Se invece manca la connessione, non funziona nessun servizio.

Client e server

Sul Web le macchine hanno due ruoli. Il client è il programma che chiede una risorsa (una pagina, un’immagine, un video): nel Web il client è il browser, come Chrome, Edge, Firefox o Safari. Il server è il programma che resta in attesa delle richieste e risponde inviando la risorsa: nel Web si chiama web server (i più diffusi sono Nginx e Apache).

Si parla di modello client-server: il client prende l’iniziativa e chiede, il server risponde. Il server non manda pagine di sua spontanea volontà: se nessuno chiede, non succede niente. Con “server” si indica spesso anche il computer su cui gira il programma server: di solito è una macchina in un data center, accesa giorno e notte e collegata a Internet con linee molto veloci.

Ruolo e macchina sono cose diverse. Lo stesso computer può fare sia da client sia da server: in laboratorio, con l’estensione Live Server di VS Code, il computer dello studente fa partire un piccolo web server e il suo stesso browser gli fa da client.

Nella storia

Il Web nasce al CERN di Ginevra, il laboratorio europeo di fisica delle particelle. Nel marzo 1989 il fisico e informatico inglese Tim Berners-Lee propose un sistema per condividere documenti fra i ricercatori, collegandoli con link (ipertesto). Il suo responsabile, Mike Sendall, scrisse sulla proposta «Vague but exciting», vago ma entusiasmante. Alla fine del 1990 funzionavano già il primo browser, il primo web server e il primo sito, info.cern.ch (https://info.cern.ch/); nell’agosto 1991 il Web fu annunciato pubblicamente. Il 30 aprile 1993 il CERN rese il Web di pubblico dominio, gratis e senza brevetti: per questo si è diffuso in tutto il mondo.

1.2Come il browser mostra la pagina

Quando aprite una pagina, secondo voi il browser riceve dal server un’“immagine” della pagina già pronta?

Il server non manda una “fotografia” della pagina, ma file di testo con istruzioni, più i file delle immagini, dei video e dei caratteri. È il browser a costruire e disegnare la pagina sullo schermo, seguendo quelle istruzioni. Per questo la stessa pagina può apparire diversa su uno schermo grande e su uno piccolo, o su due browser diversi.

I passi principali

  1. Il browser riceve il file HTML e lo legge dall’alto in basso, riga per riga: scopre quali elementi ci sono (titoli, paragrafi, immagini, link) e come sono annidati uno dentro l’altro.
  2. Mentre legge, trova i riferimenti ad altri file (fogli di stile CSS, immagini, script JavaScript, caratteri) e li chiede al server, uno per uno: ogni file è una richiesta separata.
  3. Applica gli stili: per ogni elemento calcola colore, dimensione, carattere, margini e posizione, combinando le regole CSS.
  4. Calcola l’impaginazione (layout): dove va ogni elemento e quanto spazio occupa, in base alla larghezza della finestra.
  5. Disegna i pixel sullo schermo (rendering, in inglese anche paint).
  6. Esegue gli script JavaScript, che possono cambiare la pagina anche dopo che è stata disegnata (per esempio quando l’utente clicca un pulsante): a ogni modifica il browser ricalcola e ridisegna la parte interessata.

Un’unica pagina comporta molte richieste: una pagina di un sito di notizie può richiedere più di cento file. Per questo il peso dei file, soprattutto delle immagini, influisce tanto sulla velocità con cui la pagina compare.

Errore tipico

«Il mio sito è uguale su tutti i computer, perché l’ho visto sul mio.»

Ogni browser disegna la pagina da solo, con la larghezza della sua finestra, i caratteri installati e le sue regole predefinite. Una pagina va provata su più browser e più larghezze di schermo, a partire dal telefono.

I browser e i loro motori

Il cuore di un browser è il motore di rendering, il programma che legge HTML e CSS e disegna la pagina, affiancato dal motore JavaScript, che esegue gli script. Oggi i motori di rendering sono soltanto tre: Blink (Chrome, Edge, Opera, Brave), Gecko (Firefox) e WebKit (Safari, e quasi tutti i browser su iPhone e iPad). Browser diversi con lo stesso motore disegnano le pagine quasi allo stesso modo.

1.3I tre linguaggi del front-end

Una pagina web moderna è scritta con tre linguaggi, ciascuno con un compito preciso. Separare i compiti rende il codice più ordinato: si può cambiare l’aspetto di tutto un sito senza toccare i contenuti, o aggiungere un comportamento senza riscrivere la pagina.

LinguaggioCompitoRisponde alla domandaEsempio
HTMLStruttura e contenutoChe cosa c’è nella pagina?«Questo è un titolo, questo un paragrafo, questa un’immagine»
CSSPresentazioneCome appare?«Il titolo è blu, grande 32 pixel, centrato»
JavaScriptComportamentoChe cosa fa quando…?«Quando clicchi il pulsante, mostra il menu»

HTML, HyperText Markup Language, è un linguaggio di markup (di “marcatura”): non dà ordini al computer, ma etichetta le parti di un testo dicendo che cosa sono. Scrivere <h1>Ricette</h1> significa “questo testo è il titolo principale”, non “disegnalo grande”.

CSS, Cascading Style Sheets (fogli di stile a cascata), è un linguaggio di stile: descrive l’aspetto degli elementi con regole del tipo “a questi elementi dai queste caratteristiche”. Non decide che cosa c’è nella pagina e non contiene istruzioni da eseguire in ordine.

JavaScript è un vero linguaggio di programmazione: ha variabili, condizioni, cicli e funzioni, e permette di far reagire la pagina a ciò che fa l’utente, di calcolare, di modificare il contenuto e di scaricare dati. È l’unico dei tre con cui si scrivono algoritmi.

Errore tipico

«Programmo in HTML.»

HTML non è un linguaggio di programmazione: non ha variabili, condizioni né cicli e non esegue calcoli; descrive la struttura di un documento. Si dice “scrivo una pagina in HTML”. Anche il CSS non è un linguaggio di programmazione; lo è JavaScript.

Esempio

Analogia: la casa. L’HTML è la struttura in muratura (muri, stanze, porte, finestre); il CSS è l’arredamento e la tinteggiatura; JavaScript è l’impianto elettrico e la domotica, che fa accendere la luce quando premi l’interruttore. Si può ridipingere la casa senza spostare i muri, come si può cambiare il CSS senza toccare l’HTML. Il limite: in una casa vera l’impianto non può spostare i muri, mentre JavaScript può aggiungere e togliere elementi HTML.

Front-end e back-end

Il front-end è la parte di un sito che arriva al browser e viene eseguita lì: HTML, CSS, JavaScript, immagini. Il back-end è la parte che gira sul server: programmi scritti in linguaggi come PHP, Python, Java o JavaScript (con Node.js), che leggono e scrivono nei database e preparano le risposte. Questo modulo riguarda solo il front-end.

Il codice del front-end è pubblico: chiunque può leggerlo dal browser (con “Visualizza sorgente” o con gli strumenti per sviluppatori). Il back-end invece resta sul server e l’utente vede solo il risultato. Ne segue una regola importante: nel codice del front-end non si mettono mai password o dati riservati.

Volete vedere il codice HTML di Instagram o di Wikipedia. Si può fare? E quello che gestisce le password degli utenti?

Errore tipico

«Java e JavaScript sono lo stesso linguaggio, o almeno parenti stretti.»

Sono due linguaggi diversi, con regole e usi diversi. Il nome “JavaScript” fu scelto nel 1995 per ragioni di marketing, sfruttando la popolarità che Java aveva allora. Come si dice tra programmatori: Java sta a JavaScript come car sta a carpet.

In laboratorio

Su una pagina reale (per esempio Wikipedia) aprire gli strumenti per sviluppatori con F12, scheda Elements / Elementi, e nel riquadro degli stili togliere la spunta ad alcune regole CSS: vedere la pagina perdere l’aspetto ma conservare il contenuto. Poi, dalle impostazioni (Ctrl+Maiusc+P, “Disable JavaScript”), disattivare JavaScript, ricaricare e provare la ricerca e i menu: che cosa smette di funzionare? Le modifiche spariscono ricaricando la pagina: si è cambiata solo la copia nel proprio browser.

1.4Anatomia di una chiamata

L’indirizzo: l’URL

Ogni risorsa del Web ha un indirizzo unico, l’URL, Uniform Resource Locator. L’URL dice con quale protocollo chiedere la risorsa, a quale server e dove si trova sul server.

https://www.scuola.it:443/corsi/informatica/index.html?classe=5#programma
ParteEsempioSignificato
Protocollo (scheme)https://Le regole con cui chiedere la risorsa
Nome dell’host (dominio)www.scuola.itIl server a cui chiedere
Porta:443Il “numero di sportello” sul server; di solito si omette (80 per HTTP, 443 per HTTPS)
Percorso (path)/corsi/informatica/index.htmlCartelle e file sul server
Parametri (query string)?classe=5Dati aggiuntivi passati al server, nella forma nome=valore separati da &
Frammento#programmaUn punto all’interno della pagina; non viene inviato al server

Se il percorso finisce con una cartella (www.scuola.it/corsi/), il server manda il file predefinito di quella cartella, di solito index.html. Per questo la pagina principale di un sito si chiama sempre index.html.

Dal nome all’indirizzo IP: il DNS

I dispositivi su Internet si identificano con indirizzi IP, numeri come 193.205.86.10, che le persone non ricordano. Il DNS, Domain Name System, è il servizio che traduce un nome di dominio nell’indirizzo IP del server. Il browser, prima di tutto, chiede al DNS “qual è l’IP di www.scuola.it?”; poi contatta il server a quell’indirizzo.

Esempio

Analogia. Il DNS funziona come la rubrica del telefono: si cerca il nome della persona e la rubrica restituisce il numero da chiamare. Il limite: la rubrica del DNS non sta in un unico posto, ma è distribuita su migliaia di server nel mondo, e le risposte vengono memorizzate per un po’ (cache) per non chiedere ogni volta.

Richiesta e risposta: HTTP

HTTP, HyperText Transfer Protocol, è il protocollo con cui il browser chiede le risorse e il server le invia. Ogni scambio è formato da una richiesta (il metodo, per esempio GET “dammi”, e il percorso della risorsa) e da una risposta, che contiene un codice di stato e, se tutto va bene, il contenuto del file.

GET /corsi/index.html HTTP/1.1
Host: www.scuola.it
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
<!DOCTYPE html>
<html lang="it"> ...

HTTP è senza memoria (stateless): ogni richiesta è indipendente dalle precedenti e il server, di per sé, non ricorda chi ha chiesto che cosa. Per “ricordare” un utente (per esempio il carrello o il login) i siti usano i cookie, piccoli dati che il browser rimanda al server a ogni richiesta.

Le famiglie si riconoscono dalla prima cifra: 2xx successo, 3xx reindirizzamento, 4xx errore del client (la richiesta è sbagliata), 5xx errore del server.

Errore tipico

«Errore 404: il sito è rotto, il server non funziona.»

Il 404 è un errore della richiesta: il server funziona benissimo, tanto che risponde, ma il file chiesto non esiste a quell’indirizzo (link sbagliato, file rinominato). Se il server fosse guasto si avrebbe un 5xx, oppure nessuna risposta.

Nella storia

Si racconta che il codice 404 venga dalla “stanza 404” del CERN in cui stava il primo server. Non ci sono prove ed è considerata una leggenda: i codici furono scelti a famiglie: il 4 iniziale indica gli errori del client, e 04 è semplicemente il quarto della serie.

HTTPS

HTTPS è HTTP con i dati cifrati (la S sta per Secure): nessuno tra il browser e il server può leggere o modificare ciò che si scambiano, e il server dimostra la sua identità con un certificato digitale. Il lucchetto nella barra degli indirizzi dice che la connessione è cifrata, non che il sito è onesto: anche un sito truffa può avere HTTPS.

Statico o dinamico

Un sito statico è formato da file già pronti (HTML, CSS, JavaScript, immagini) che il server invia così come sono, uguali per tutti. Per cambiare il contenuto bisogna modificare i file e ricaricarli sul server. Un sito statico può comunque essere interattivo: JavaScript gira nel browser e può far reagire la pagina, fare calcoli e perfino scaricare dati.

Un sito dinamico costruisce la pagina al momento della richiesta: sul server un programma legge i dati da un database, li inserisce in un modello e genera l’HTML. Pagine diverse per utenti diversi (il proprio profilo, il proprio carrello, i propri voti sul registro elettronico) richiedono un sito dinamico.

Sito staticoSito dinamico
PaginaFile già prontoGenerata a ogni richiesta
ContenutoUguale per tuttiPuò cambiare per ogni utente

Velocità e costoMolto veloce, hosting anche gratuitoPiù lento e costoso da ospitare

EsempiSito di presentazione, portfolio, documentazione, sito di un eventoSocial network, e-commerce, registro elettronico, home banking

Errore tipico

«Un sito statico è un sito dove non si muove niente.»

“Statico” si riferisce a come il server fornisce le pagine (file già pronti), non all’aspetto. Un sito statico può avere animazioni, giochi, quiz e menu interattivi, perché tutto questo lo fa JavaScript nel browser. Non può invece salvare dati sul server o mostrare a ogni utente contenuti diversi presi da un database.

Il sito che costruiremo noi: statico o dinamico? E il registro elettronico?

Molti siti oggi sono ibridi: le pagine sono file statici, e JavaScript chiede i dati a un servizio esterno (un’API, 4.14) quando servono. Anche i grandi siti “di contenuti” (blog, documentazione) spesso generano in anticipo tutte le pagine come file statici, perché così sono più veloci e sicuri.

In laboratorio

In un browser aprire gli strumenti per sviluppatori (F12), scheda Network / Rete, e ricaricare la home del sito della scuola. Osservare la lista delle richieste: quante sono, di che tipo (documento, CSS, immagini, script), con quale codice di stato, quanto pesano in tutto. Poi scrivere nella barra un indirizzo inesistente dello stesso sito e trovare il 404. Infine cliccare il lucchetto e leggere a chi è intestato il certificato.

Ricorda

  • Internet è la rete mondiale che collega i dispositivi; il Web è un servizio che funziona su Internet, fatto di pagine collegate da link.
  • Nel modello client-server il client (il browser) chiede una risorsa e il server (il web server) risponde inviandola; ruolo e macchina sono cose diverse.
  • Il Web è stato inventato da Tim Berners-Lee al CERN tra il 1989 e il 1991 ed è stato reso libero nel 1993.
  • Il server non invia una pagina già disegnata ma file di testo con istruzioni: il browser chiede uno per uno i file collegati, applica gli stili, impagina, disegna ed esegue gli script.
  • Ogni browser disegna la pagina da solo: una pagina va provata su più browser e più larghezze di schermo, a partire dal telefono.
  • HTML descrive la struttura e il contenuto, CSS l’aspetto, JavaScript il comportamento; solo JavaScript è un linguaggio di programmazione.
  • Il front-end (HTML, CSS, JS) arriva al browser ed è leggibile da tutti; il back-end gira sul server; nel front-end non si mettono mai dati riservati.
  • L’URL indica protocollo, dominio, eventuale porta, percorso, parametri e frammento; il file predefinito di una cartella è index.html.
  • Il DNS traduce il nome di dominio nell’indirizzo IP del server; poi il browser invia una richiesta HTTP e riceve una risposta con un codice di stato (2xx successo, 3xx reindirizzamento, 4xx errore del client, 5xx errore del server).
  • HTTPS cifra la comunicazione e verifica il server con un certificato; il lucchetto non garantisce che il sito sia onesto.
  • Un sito statico è fatto di file già pronti inviati uguali a tutti, ma può essere interattivo grazie a JavaScript; un sito dinamico genera le pagine sul server con un programma e un database.
